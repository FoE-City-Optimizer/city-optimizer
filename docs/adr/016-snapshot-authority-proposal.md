# ADR-016: Snapshot schema authority and compatibility (proposal)

**Status:** Proposed. **Issue:** [#26](https://github.com/FoE-City-Optimizer/city-optimizer/issues/26). **Governing decision:** [ADR-005](005-snapshot.md), Accepted. This proposal does not finalize Snapshot v1.

## Context

ADR-005 requires one authority for a project-owned versioned snapshot and validation at each trust boundary. The privacy-reviewed [#24 replay](../research/issue-24-real-city-fixture.md) and [#25 mechanics review](../research/issue-25-city-mechanics.md) prove selected presence, joins, and shapes but leave coordinate omission, blocked-area meaning, generic road demand, universal root identity, and special relationships unresolved. A source replay must not become a canonical snapshot by renaming its keys.

The [#26 comparison](../research/issue-26-snapshot-authority.md) exercised a small synthetic shape through JSON Schema Draft 2020-12 with Ajv 8.20.0 and Python jsonschema 4.26.0, TypeScript-first Zod 4.6.5 with generated JSON Schema, and manual validators. All six paths agreed on ten syntax cases. That narrow agreement does not prove complete generator semantics or domain correctness. JSON Schema to TypeScript 16.0.0 generated a declaration; its `maxItems: 3` became a union of fixed tuples, a concrete readability cost.

## Proposed decision

1. Make a reviewed JSON Schema Draft 2020-12 document in `packages/contracts` the **single wire-shape authority**. Generate TypeScript declarations from it; use Ajv's Draft 2020-12 validator on TypeScript boundaries and `jsonschema.Draft202012Validator` on Python boundaries. Pin exact tool versions and lockfiles, validate the schema itself, check generated output for drift, and run one shared positive/negative fixture corpus through both runtimes. Generated types alone never certify untrusted input.
2. Keep domain compilation separate from schema validation. A structurally valid `DOUBLE` value, unresolved diagnostic, duplicate ID, bad root count, overlap, or uncertain source mapping can still make a city ineligible. The compiler must emit bounded stable diagnostic codes, never raw values. Solver input is a different, smaller validated type.
3. Use explicit `major.minor` schema versions. A receiver validates against an explicitly supported exact version before parsing; unknown majors and unknown minors reject with `VERSION_UNSUPPORTED`. Within major 1, a minor may add an optional field only after every receiving boundary implements that exact minor. Old validators remain strict, so an additive minor is **not** automatically forward-compatible. Any removal, changed meaning, new required field, enum expansion that old readers cannot handle, or coordinate/identity reinterpretation requires a new major or an explicitly demonstrated compatible migration.
4. Reject unknown properties and enum values, implicit defaults for critical fields, nonfinite/noninteger/out-of-bound geometry, oversize payloads, duplicate JSON member names, and excessive nesting. Bound raw bytes before JSON parse and bound arrays/strings/cell counts during validation. The final numeric limits need a separate resource benchmark and Security & Privacy review; the experiment's 0–63/3-instance bounds are not product limits.
5. Scope instance and definition references to one snapshot only. Do not expose source IDs, replay pseudonyms, or a cross-capture identity claim as a v1 guarantee. Specify origin and unit as integer city-grid cells, with axis direction and normalization rule accepted only after source-coordinate evidence. Store source/adapter revision as bounded, nonidentifying compatibility metadata, not a game-build claim inferred from an asset filename.
6. Extension projects the minimum allowlist and validates before handoff. Treat page-origin messages as untrusted. API independently rechecks version, bytes, syntax, and semantic eligibility before job admission. Solver accepts only compiled eligible domain input and rechecks its own input boundary. Diagnostics and logs contain codes/counts, not raw city data.

## Alternatives considered

| Option                                               | Benefit                                                                                                                                | Cost / reason not proposed                                                                                                                                                                                                      |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| JSON Schema-first                                    | Language-neutral wire authority; standard required, enum, bounds, and closed objects; both runtimes validated the same synthetic cases | Generated TS types cannot encode all domain invariants; explicit generator review and runtime validators remain necessary                                                                                                       |
| TypeScript-first Zod, generate JSON Schema           | Concise TS runtime definition; synthetic Zod conversion validated in Python                                                            | Generated schema is an extra artifact whose representability must be audited; Zod documents unrepresentable checks and transformations. Python consumer depends on export fidelity                                              |
| Hand-maintained TS/Python DTOs and conformance tests | Few generator dependencies; easy to start                                                                                              | Two editable authorities invite drift. Ten matching synthetic cases do not guarantee later edits stay synchronized; contradicts ADR-005's single-authority requirement unless both are formally validated against one authority |

## Consequences and proof gates

This proposal adds a schema/generator maintenance and cross-runtime CI obligation. It does not authorize a production schema, collector, API job, or solver feature. Architecture & Planning must accept or revise this ADR and coordinate eligibility/claims with proposed [ADR-011](011-special-buildings.md). Before calling Snapshot v1 final, establish omitted-coordinate, available/blocked, road-demand, Town Hall, and unsupported-mechanic semantics, settle bounded metadata/diagnostics and resource limits, and demonstrate TS/Python conformance on the full reviewed contract. Issue #23 is closed, but its merged narrow Chrome probe does not supply the complete acquisition/update and message-boundary evidence required by open Epic #2; that proof and a design-specific Security & Privacy review remain prerequisites to production collector refinement.
