# Issue #26 — Snapshot v1 schema authority and compatibility research

**Status:** Research conclusion, 2026-09-25. **Confidence:** high for reviewed replay facts and the narrow local conformance result; medium for JSON Schema-first as the preferred authority; low for unresolved game-source semantics. This is a candidate contract and [proposed ADR-016](../adr/016-snapshot-authority-proposal.md), not a final Snapshot v1 or an accepted decision.

## A–B. Question and conclusion

What single schema authority, versioning policy, and TypeScript/Python conformance method should govern project-owned Canonical City Snapshot v1, given verified M1 fields and unresolved source semantics?

**Project recommendation:** JSON Schema Draft 2020-12 as the wire-shape authority, with generated TypeScript declarations, Ajv Draft 2020-12 validation in TypeScript, Python `jsonschema` Draft 2020-12 validation, and shared cross-runtime cases. Pin validators and generator, check generated output for drift, and compile semantic/domain input separately. The synthetic experiment confirms all three studied strategies can agree on ten basic syntax cases; it does not validate a real city or settle which authority Architecture & Planning will accept. The #24 fixture cannot yet yield a complete, solver-eligible v1 because critical source meanings remain unknown.

## E. Verified facts, external claims, inference, recommendation

Collector dependency evidence: the [#23 issue](https://github.com/FoE-City-Optimizer/city-optimizer/issues/23) was read through `gh` on 2026-09-25 and is closed as completed at 19:47 UTC. Its [merged PR #32](https://github.com/FoE-City-Optimizer/city-optimizer/pull/32) documents a narrow Chrome 154 startup presence-marker bridge, not complete field projection or update coverage. The open [Epic #2](https://github.com/FoE-City-Optimizer/city-optimizer/issues/2), read the same day, still requires those facts and a design-specific privacy review. Issue state is planning evidence, not browser-behavior proof.

**Verified facts:** Unchanged #24 replay passes twice: 419 source instances, 399 retained ordinary instances, 135 retained definition joins, 124 explicit-position 1×1 streets, one explicit-position 6×7 `main_building` candidate, 234 unlocked rectangles, 49 blocked positions, and 20 aggregate-only special/off-grid entries. Entity axes omit x 10 times and y 11 times; unlocked rectangles omit x 10/y 11; blocked positions omit x 8/y 7. No explicit coordinate zero appears in these trails. The #25 checker reports 73 generic definitions with no street requirement field; 201 retained generic instances refer to those definitions. Its zero-coordinate diagnostic has no ordinary overlap; substituting one gives 84 overlaps. Neither is a serialization proof.

**External claims:** JSON Schema Draft 2020-12 and the named tools offer the documented validation/generation capabilities in the evidence register. These are software capabilities, not evidence about Forge of Empires semantics.

**Inference:** The reviewed replay is useful as a source-presence/derivation regression case but cannot be transformed into a complete canonical map without inventing missing coordinates and other rules. A strict wire schema plus a separate semantic compiler preserves this distinction. All strategies passed the small synthetic corpus, so the recommendation is based on authority/drift/reviewability tradeoffs, not a claimed performance or correctness victory.

**Project recommendation:** Use the proposal in ADR-016 for Architecture & Planning review. Keep unproven semantics as bounded diagnostics in a research/geometry representation; a full valid/optimal claim must fail closed. No accepted ADR is contradicted by the observed evidence. The M1 plan's expectation of a finalized Snapshot v1 is still an open gate, not a conclusion of this research.

Exact product limits and final generator choice require a full candidate schema and CI comparison.

## Candidate version, validation and diagnostic policy

The proposed wire version is a string `1.0` only after acceptance. A receiver dispatches on **exact** supported versions; `1.1`, `2.0`, malformed and absent versions reject deterministically as `VERSION_UNSUPPORTED`/`VERSION_MISSING`. A future optional minor field is accepted only after all relevant receiver versions explicitly support that minor; strict old readers reject it. Never silently strip unknown keys. Breaking interpretation, requiredness, enum, coordinate or identity changes require a major version or a demonstrated migration. Retained results must record the schema version separately from solver/model versions.

Proposed canonical units are integer grid tiles with explicit axis direction/origin and no floating values. Coordinate and dimension maxima, total cell count, entity/road/diagnostic counts, string lengths, raw JSON byte limit, and nesting depth all need fixed caps before release. Bound bytes before parsing and cap expansion of rectangles to cells. Reject duplicate JSON member names in a parser layer (ordinary `JSON.parse` overwrites them), duplicate instance IDs in a semantic layer, and duplicate cells where canonical sets require uniqueness. Enumerations are closed; unknown road requirements reject rather than become `NONE`. Diagnostics should be stable **project codes**, capped in count, ordered by fixed validation stage then canonical instance index, and carry no raw identifiers/coordinates. Validation libraries' prose and error ordering must not be the external error contract.

Boundary sequence: the extension allowlists source fields, derives a candidate, and validates before handoff; MAIN/page messages and submitted snapshots are untrusted. The API applies raw byte/depth/resource limits, exact-version dispatch, schema validation and independent semantic eligibility checks. The solver receives a separately compiled, bounded eligible domain input and validates that input; it never receives source responses or browser messages. A research/geometry view may retain bounded `COORDINATE_UNRESOLVED`, `BLOCKED_SEMANTICS_UNKNOWN`, `ROAD_DEMAND_UNKNOWN`, `ROOT_UNVERIFIED`, or `SPECIAL_RELATIONSHIP_UNSUPPORTED` diagnostics. Those states prohibit a full-validity or optimality claim when relevant. The final naming and representation of such codes belong to the accepted contract decision.

**Assumptions no longer safe:** omitted axis = zero, omitted generic street field = `NONE`, blocked positions always subtract from unlocked geometry, `main_building` universally identifies the road root, every generic entity is ordinary, or 399 retained entries describe the entire functional city. No Accepted ADR is contradicted; the charter's trust/validity principle is strengthened. A real-city full-positive contract case remains unavailable without further source research. Two high-quality external sources did not materially disagree in this pass; the stop/escalation boundary is the unresolved game semantics, not a schema-tool conflict.

## I–J. Project impact and recommendation

Architecture & Planning can compare the three authority strategies and decide the proposed ADR-016 language-neutral wire authority, explicit-version policy and validation ownership. `packages/contracts` would later own the schema/generated TS boundary; `packages/domain` would later own semantic compilation rules, with Python consuming only compiled eligible input. Proposed ADR-011 must define the claims/eligibility policy for chains, sets and adjacency-sensitive buildings. Epic #21 **cannot** call Snapshot v1 final until source semantics, a complete field/limit design, accepted ADR, and full TS/Python conformance exist. Epic #22 and the open collector Epic #2 remain separate evidence gates. Issue #23 is **closed** as of 2026-09-25 19:47 UTC, yet its merged PR #32 demonstrated only a narrow Chrome presence-marker bridge; its issue body and the open Epic #2 still call for exact city-field projection, updates, loss handling and a concrete privacy review before production collector refinement. The issue state must not be mistaken for production readiness.

Security/privacy posture is unchanged: the #24 exact-artifact approval and residual layout-recognition risk remain, and this work added only synthetic cases. No private capture, gameplay action, raw source dump, upload, backend retention or new real-city fixture occurred. A future fixture byte change or new city/build sample requires its own exact-artifact review.
