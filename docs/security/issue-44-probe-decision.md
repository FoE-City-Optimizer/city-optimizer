## Permitted host, operation, fields, and duration

- **Host and frame:** only the owner's already authorized main city at `https://pl4.forgeofempires.com/game/*`, top frame. Both manifest entries and runtime checks restrict origin and path; the XHR observer selects the exact same-origin `/game/json` path.
- **Operation:** load this unpacked directory once; the owner reloads the already open city once, observes one startup, performs one reversible city change manually, reads the local diagnostic panel, then removes the extension and reloads the game tab. The probe must not initiate a game action. If the selected source is missed or an unexpected shape appears, record `stale`/`unsupported` and stop this run rather than broadening collection.
- **Duration:** one continuous observation session, at most 15 minutes from loading the extension. Remove it immediately after the single change or sooner if the game behaves unexpectedly. This is an owner procedure; the probe has no timer that enforces it.
- **Temporary page-memory fields:** for selected startup entities, `id`, `cityentity_id`, `type`, `x`, `y`; for unlocked areas, `x`, `y`, `width`, `length`; for blocked areas, presence of `x`/`y`; for selected move rows, the same entity identity/class and position fields. The MAIN script uses temporary IDs and positions only to compare a move against startup. No raw response or reverse map is retained in storage.
- **MAIN-to-ISOLATED message fields:** exactly `type`, `version`, `source`, `state`, `reason`, `entities`, `roads`, `areas`, `blocked`, `missingEntityPosition`, `missingAreaPosition`, `missingBlockedPosition`, `updateEntries`, `changedPositions`. Only aggregate counts/status leave page memory for the isolated local panel; no message goes to a service worker or network endpoint.
- **Research record:** only panel source/status and aggregate counts, Chrome version, a separately observed game asset fingerprint, and the owner's action category. Do not record an ID, coordinate, URL/query, raw response, header, cookie, credential, token, account/social/chat data, page screenshot, or recognizable city layout. The panel is a diagnostic aid; its numbers must not be fed into Snapshot v1 as authoritative city data.

## Security & Privacy findings

| Boundary                      | Finding and disposition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Permissions                   | The MV3 manifest has two static content scripts for one exact HTTPS world/path and no `permissions`, `host_permissions`, background worker, or web-accessible resources. Chrome's default top-frame behavior is reinforced by both scripts' top-window checks. Acceptable for this one host-scoped run.                                                                                                                                                                                                                                                           |
| Selection and minimization    | MAIN wraps XHR `open`/`send`, observes completed status-200 responses at the exact `/game/json` path, and selects only `StartupService.getData`/`city_map` and `CityMapService.moveEntities` for diagnostics. A text response is transiently parsed in full before selecting rows; no unrelated entry is saved, displayed, or sent across the bridge. Temporary selected IDs/coordinates stay in page memory. Acceptable for this one run.                                                                                                                        |
| Trust boundary                | MAIN and page code share an execution world. The isolated bridge checks source window, exact origin, exact keys, enumerated values, safe integer bounds, and a 32-accepted-event limit, then renders text with `textContent`. A page script can still forge a valid message, race the cap, or alter the DOM panel. The panel has no authority to trigger a privileged action or establish source authenticity. Accept only as untrusted diagnostic output.                                                                                                        |
| Resource and compatibility    | Selected startup/move arrays are rejected above 10,000 entries; text parsing is guarded at 6,000,000 characters; both sides cap emitted/accepted messages at 32. The JSON response path and top-level response array have no local size cap, and the hook continues inspecting after the message budget. XHR method wrapping can change page-level function identity or timing. Accept the residual risk for one 15-minute owner-supervised run; stop on lag or visible disruption. These are follow-up design issues for any repeatable or production collector. |
| Storage, upload, and gameplay | Static review found no persistent storage, file write, upload, telemetry, request-body/header read, cookie/credential/token access, game command, click automation, or response mutation. The wrapper calls the original XHR methods. This does not establish that the game will behave identically in a live run.                                                                                                                                                                                                                                                |
| Data validation               | The probe generates no canonical snapshot. Its shape checks reject unknown classes, duplicate startup IDs, unexpected selected types and malformed positions. A `partial` status is not complete geometry or valid solver input.                                                                                                                                                                                                                                                                                                                                  |
| Dependencies                  | The unpacked probe has no third-party runtime dependency, service worker, or build step. The Node synthetic check uses built-in modules only.                                                                                                                                                                                                                                                                                                                                                                                                                     |

**Required code/design changes before this one run:** none. The short run, explicit stop rule, and no-authority interpretation are conditions of this approval. Hard processing caps, stronger coverage and provenance belong to a separately reviewed design before repeated use or production collection.

## Evidence and residual limits

The [synthetic check](../research/issue-40-chrome-probe/check-probe.mjs) and syntax checks for both scripts passed on 2026-09-26; static inspection covered all six exact files. A separate one-off Node VM check of the unchanged bridge confirmed that a structurally valid same-page forged envelope reaches the panel, while an extra field and a wrong origin are rejected. This confirms the documented trust limit; the VM is not a Chrome isolation test. This review did not install the extension or observe a live game response. The existing committed harness exercises MAIN startup/move selection and malformed cases but not the full bridge or a real browser. Passing local checks cannot establish runtime noninterference.

The panel cannot authenticate page facts or prove complete city geometry. It does not load definitions, interpret omitted coordinates, establish blocked-area semantics, resolve road requirements, or confirm that all updates were observed. A live `partial` diagnostic is not a complete city, a validated snapshot, or a solver-ready input. Any discrepancy or loss must remain visible in #45's research report.
